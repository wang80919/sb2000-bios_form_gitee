# ASM 开发文档

`ASM.EXE` 是运行在 SB-DOS 下的 6502 汇编器，用 fcdev 的 C（cc65）开发，把汇编源文件汇编成 SB-DOS 的 EXE。源文件的写法见 [汇编语法.md](汇编语法.md)，使用方法见 [../README.md](../README.md)。

## 1. 构建

```powershell
npm install
npm run build
```

产物为 `build/sb2000/ASM.EXE`（45056 字节）。构建时链接器会报“Segment ‘BSS’ isn't aligned properly”的警告，这是 fcdev 多页模板的已知现象，不影响运行。运行与调试用 `fcdev.json` 里配置的 BIOS，调试服务的用法见 fcdev 文档。

## 2. 目录

| 文件 | 内容 |
| --- | --- |
| `src/main.c` | 程序入口：调用 `asm_run`，等待按键后返回 DOS |
| `src/assembler.h` | 汇编状态 `AsmState`、符号记录、行类别与寻址方式常量、各库页的函数声明 |
| `src/assembler.c` | 源文件读取、命令行、符号表、表达式、行解析、两遍汇编、跨银行调用、EXE 输出 |
| `src/opcodes.h`、`src/opcodes.c` | 官方 6502 指令表（助记符、寻址方式、机器码）与查找函数 |
| `src/messages.h` | 全部中文提示与错误信息，GB2312 字节串，每条一个宏 |
| `fcdev.json` | 目标 `sb2000`，`banks` 为 8 |
| `examples/hello.asm` | 控制台输出“你好，小霸王！”的示例，用 `.include` 引入符号文件 |
| `examples/SB2000.INC` | 系统接口的符号文件，复制自 fcdev 的 `sb2000.inc` |

## 3. 内存与库页

程序是多页程序：`$8000` 到 `$9FFF` 为常驻区，`$A000` 到 `$AFFF` 是库页窗口，同一时间只映射一个库页。函数放进哪个库页由 `SB_BANK_BEGIN(n)` 到 `SB_BANK_END()` 决定；跨库页调用由 `SB_BANK_CALLS_BEGIN(n)` 声明，调用时自动换页。

| 位置 | 内容 |
| --- | --- |
| 常驻区 | `main`、`asm_state`（全部汇编状态）、转大写、去空格、十六进制转换、判断 `.include` 行、常量行位图、写输出、保存错误、读路径、显示错误；这些函数很小而且每行都要用，放在常驻区可以省掉换页蹦床的开销 |
| 库页 1 | 命令行取词、补扩展名、`asm_run`（总流程）、`asm_enter_include`、释放文件 |
| 库页 2 | 符号表（哈希、查找、登记、清空）、数字解析、`asm_resolve_expression` |
| 库页 3 | `asm_classify_operand`（识别寻址方式）、零页判断 |
| 库页 4 | 指令表与 `asm_find_opcode` |
| 库页 5 | `.ascii` 长度检查、`asm_parse_current_line`（解析一行） |
| 库页 6 | 加符号、推进地址、标签校验、预扫描（含快速通道）、`asm_first_pass` |
| 库页 7 | 跨银行调用运行时代码、输出偏移、取操作数表达式、数据与字符串输出、`.bankcall` 输出、`asm_second_pass` |
| 库页 8 | 读行：读入缓冲、`asm_next_line`、`asm_reset_source`、切换当前文件 |

约定：

- 传给另一个库页的指针必须指向常驻区或全局缓冲，不能指向调用者所在库页里的数据。所以状态、行缓冲和输出缓冲都放在 `asm_state`。
- 一个库页最大 4 KiB，新增代码后用 `build/obj/sb2000/asm/asm.map` 检查每个库页是否还放得下。
- 换页蹦床每次要换两次窗口，开销不小：同一个库页里的函数互相调用也经过蹦床（只要在 `SB_BANK_CALLS_BEGIN` 里声明过）。所以每行都要用的小函数放常驻区，库页内部的调用用 `static` 版本。
- 常驻区几乎用满（链接映射里 `BSS` 段的结尾离 `$A000` 只剩几十个字节），新增常驻代码或变量前，先把不常用的函数挪进库页。
- 热路径上避免 32 位运算：cc65 的长整数运算很慢，读行时只在换块时用 `unsigned long`，块内用 8 位下标。
- 新增提示或错误信息时，在 `src/messages.h` 里加宏，写成 GB2312 字节串：每个汉字 2 个字节，十六进制转义后面紧跟数字或字母时要把字符串拆成两段（例如 `"\xB8\xF6" "1"`）；错误信息不超过 30 个字节。

## 4. 总流程

`asm_run` 的步骤：

1. 从 `SB_CMD_TAIL` 取命令行里的第一个词为源文件，第二个词为输出文件；没有源文件时提示输入。源文件没有扩展名时补 `.ASM`，没有输出文件时用源文件主名加 `.EXE`（路径最长 28 个字符）。
2. 显示“汇编中...”，`sb_file_load` 把源文件装入扩展 RAM，记下首页和字节数；文件为空时报错。
3. 申请 10 页作符号表。
4. 第一遍 `asm_first_pass`（先预扫描常量），第二遍 `asm_second_pass`；出错时 `asm_show_error` 打印行号和原因。
5. 释放输出映像、符号表和源文件占用的页，返回。

源文件不是逐字节读的：`asm_next_line`（库页 8）每次从扩展 RAM 整块读 128 字节到 `read_buffer`，块内只用 8 位下标；分号之后的注释不保存，用 `memchr` 直接跳到行尾，所以注释写多长都不占行缓冲。`asm_next_line` 去掉 CR，遇到 LF 结束一行。

### 包含文件

- `.include "文件名"` 由行解析识别（`ASM_KIND_INCLUDE`），三遍扫描（预扫描、第一遍、第二遍）遇到它都调用 `asm_enter_include`。
- 每个文件只装入一次：`files[]`（最多 8 个，序号 0 是主文件）按路径记着首页、页数和大小，再次包含同一个文件直接复用；汇编结束时 `asm_free_files` 统一释放。
- 嵌套用 `frames[]` 保存父文件的序号、读取位置和行号，最多 4 层；`asm_next_line` 读到包含文件末尾时自动弹出，回到父文件继续读。
- 行号是各文件自己的行号，出错时 `error_file` 记着出错的文件，不是主文件就先显示它的名字。
- 符号登记的定义行用 `line_seq`：所有文件的行连续编号，每遍扫描里同一行的编号相同。

## 5. 第一遍

目的：收集符号，算出常驻区和各银行的长度。

- 预扫描（`asm_prescan_constants`）：先扫一遍源文件（包含文件也读进来），把能求值的常量全部登记进符号表。整行只是“名字 = 数字”的行走快速通道 `asm_prescan_simple_constant`，直接登记，不做完整的行解析（符号文件里几乎全是这种行）；其余含等号的行走 `asm_parse_current_line`（`prescan` 标志下只处理常量定义和 `.include`），求不出值的常量（依赖还没定义的标签）跳过，留到后面按出现顺序登记。登记过的常量行记进位图 `constant_lines`（前 1024 行），第一遍和第二遍遇到这些行直接跳过。
- 位置计数器：每个银行一个（`bank_addresses[]`），常驻区从 `$8008` 起，银行从 `$A000` 起。`.bank n` 切换计数器，`.org` 修改当前银行的计数器。
- 每行调用 `asm_parse_current_line`，得到类别（空行、指令、`.org`、`.bank`、`.byte`、`.word`、`.ascii`、`.bankcall`、常量）、标签、寻址方式和长度。
- 常量和标签用 `asm_add_symbol` 写入符号表（最终由库页 2 的 `asm_symbol_define` 完成）。符号表放在扩展 RAM 的 10 页里：开头 512 字节是 256 个哈希桶，之后是按登记顺序排列的 `AsmSymbol`（名字 32 字节、值、所属银行、定义所在行的序号、同一个桶里下一个符号的序号），最多 1024 个。查找时按名字算哈希，只比较同一个桶里的几个符号。预扫描登记过的常量，第一遍遇到同一行时跳过（靠行序号识别），遇到其他行里的同名定义则报“符号重复定义”。
- `asm_advance_address` 推进计数器并检查范围：常驻区不超过 `$9FF0`，银行不超过 `$B000`。
- 结束时 `helper_address` 取常驻区的最终位置，其后保留 128 字节放运行时代码；超过 `$9FF0` 报“没有空间放跨银行代码”。

行长度在第一遍就必须确定，所以零页与绝对的选择在解析时完成：操作数是数字或此时已登记的常量，且不超过 `$FF` 才算零页，并且该指令必须有零页形式，没有时（如 `JMP`、`STA 零页,Y`）退回绝对形式（`asm_zero_page_or_absolute`）。由于常量已经预扫描登记，常量先使用后定义时两遍的选择一致。值依赖标签的常量预扫描时求不出值，如果在定义之前被使用，两遍会选出不同的长度，由第二遍的标签地址校验报错。

## 6. 第二遍

目的：生成映像并保存。

1. 映像页数为 `最大银行号 + 3`，最少 4 页；申请连续页，整体清零。
2. 写 8 字节文件头 `4C 08 80 AA 55 00 00 00`，把 `$9FF0`（当前银行）初始化为 1。
3. 有 `.bankcall` 时，在 `helper_address` 写入运行时代码。
4. 逐行解析并输出：
   - 定义了标签的行，先用 `asm_check_label` 核对符号表里的地址和银行与当前位置一致，不一致说明两遍对某一行长度的判断不同，报“标签地址前后不一致”，不会生成错位的 EXE。
   - 指令：查指令表取机器码，用 `asm_extract_expression` 取出操作数表达式，`asm_resolve_expression` 求值；相对寻址算偏移并检查范围和银行；立即数和零页检查 `$FF`。
   - `.byte`、`.word`、`.ascii`、`.bankcall`：各自编码后写入。
   - 所有输出经 `asm_write_line`，由 `asm_output_offset` 换算成映像里的偏移。
5. `sb_file_save` 把整个映像写成输出文件。

映像布局（`asm_output_offset`）：

| 银行 | 映像偏移 |
| --- | --- |
| 0（常驻区） | 地址 - `$8000`，占第 0、1 页 |
| 1 | `$2000` + 地址 - `$A000`，第 2 页 |
| n（n≥2） | `(n + 2) × $1000` + 地址 - `$A000`，第 n+2 页；第 3 页是栈页，保持为空 |

## 7. 跨银行调用

`.bankcall n, 标签` 在调用处展开成 24 字节：

```text
STA $9FF4      保存 A
STX $9FF5      保存 X
LDA #n         STA $9FF1    目标银行
LDA #<标签     STA $9FF2    目标地址低字节
LDA #>标签     STA $9FF3    目标地址高字节
JSR 运行时代码
```

运行时代码共 101 字节，放在 `helper_address`，做这些事：

1. 把 `$9FF0`（当前银行）压栈，改成目标银行。
2. 由银行号算出页号（银行 1 为 2，其余为 n+2），加上程序文件头 `$8005` 里的起始页，写入系统变量，调用系统服务 `$FFF0`（功能号 `$29`，映射窗口 2）把目标页映射到 `$A000`。
3. 读回 A、X，`JSR` 到末尾的 `JMP ($9FF2)` 进入目标代码。
4. 目标 `RTS` 回来后保存 A、X，弹出原银行号，用同样方式映射回原页，恢复 A、X 后 `RTS`。

变量区 `$9FF0` 到 `$9FF5`：当前银行、目标银行、目标地址低高字节、A、X。

## 8. 已知限制

- 值依赖标签的常量（如 `LO = <LABEL`）需要写在使用它的指令之前，否则第二遍报“标签地址前后不一致”。
- 分支目标必须是同一银行里的标签，不能是数字或常量。
- 预扫描只识别以 `.include` 开头的行；`标签: .include "文件"` 这种带标签的写法不会在预扫描里进入该文件，那个文件里的常量要先于使用它们的地方定义。
- 符号文件 SB2000.INC（约 31 KB、350 多个符号）在模拟器里约需 1000 帧（十几秒）汇编完；时间主要花在读入、预扫描和登记符号的扩展 RAM 读写上。
- 符号表固定 1024 项、10 页；源文件、包含文件、符号表和输出映像要同时放进扩展 RAM。
- 所有提示和错误信息都是中文（GB2312 字节串，集中放在 `src/messages.h`），错误信息最长 30 个字节，保证在 31 列的屏幕上一行显示完。

## 9. 验证方法

仓库里没有自动化测试，修改后用模拟器验证：

1. `npm run build` 生成 `ASM.EXE`，必要时先构建 `../edit` 得到 `EDIT.EXE`。
2. 用 fcdev 的调试服务启动模拟器（`fcdev run --debug --port 端口`），把 `ASM.EXE` 和测试源文件做成软盘镜像挂载。
3. 在 DOS 提示符输入 `ASM 文件名`，读回输出文件，和手算的机器码逐字节比较；跨银行调用要在 DOS 里运行生成的 EXE，再读 CPU 内存核对结果。
4. 出错用例截图，确认行号和原因显示完整。
