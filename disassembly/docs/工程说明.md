# 反汇编工程说明

本文说明 `disassembly/` 里反汇编工程的组成、命令、ROM 页地图和约定。目标、进度与后续计划见 [计划与进度](计划与进度.md)，验证口径与方法见 [验证方法](验证方法.md)，发现的问题与结论见 [问题与结论登记](问题与结论登记.md)，全部文档的地图见 [README](README.md)。

## 1. 工程组成

| 路径 | 内容 |
| --- | --- |
| `tools/` | 命令行与库：模拟器客户端、反汇编、CDL 清单、软盘镜像、API 日志汇总、文档生成、验证运行；汇编器与构建脚本在 [../bios/tools/](../../bios/tools/) |
| `verify/` | 验证用例与辅助库，格式见 [verify/README.md](../verify/README.md) |
| `test/` | `node:test` 单元测试，`npm test` 运行 |
| `docs/` | 本目录的文档，见 [README](README.md) |
| `out/` | 生成物：`cdl/` 代码数据标记、`verify/` 验证结果、`coverage/` 覆盖率、`api/` 调用汇总等；都可重新生成，整个目录被 `.gitignore` 忽略 |

BIOS 的源码工程在仓库根目录的 [bios/](../../bios/)（目录结构、清单格式、汇编语法、命名与注释规范见 [bios/README.md](../../bios/README.md)），这里的分析、验证工具通过 `tools/config.mjs` 的 `BIOS_DIR` 引用它，构建出的 ROM 在 `bios/build/`。原始 ROM、官方软盘、模拟器在仓库根目录：`reference/rom/SB2K_BIOS.NES`、`reference/floppy-images/`（路径常量在 `tools/config.mjs`）；模拟器在与本仓库同级的 fcdev 仓库的 `virtuanes/` 里维护。

## 3. 采集与分析流程

`tools/` 里的脚本用 fcdev 仓库 `virtuanes/` 里带调试服务的模拟器采集“哪些字节被当作代码或数据”（CDL），供覆盖率统计使用。模拟器的编译与调试服务命令见 fcdev 仓库 `virtuanes/README.md`。

1. 启动带调试服务的模拟器（以下命令都在 `disassembly/` 目录里运行）：

   ```powershell
   node tools/sb2kdbg.mjs --launch
   ```

2. 采集并生成系统调用表：

   ```powershell
   node tools/collect-cdl.mjs full
   node tools/verify-dispatch.mjs out/api/full-ff16.log
   node tools/render-api-doc.mjs
   ```

   `collect-cdl.mjs` 的场景有 `boot`、`apps`、`full`（DOS 命令）和 `wps`、`game`（真实软件镜像，见脚本头部说明）。

   真实软件的采集与分析用官方软盘（`reference/floppy-images/FLPPY0…`-`FLPPY21…`，都是 1.44MB 的原始 `.img`），工具直接从那里按盘号取用（WPS 是 1 号，游戏集锦 027 是 20 号），`wps`、`game` 场景也一样：

   ```powershell
   node tools/export-image-tree.mjs --all
   node tools/exe-api-scan.mjs out/official
   node tools/collect-cdl.mjs wps
   ```

   `list-image.mjs <镜像> <目录>` 列出并导出镜像根目录里的文件；`export-image-tree.mjs <镜像或官方软盘盘号> <目录>` 连子目录一起导出，`--all` 把 22 张官方软盘全部导出到 `out/official/disk<两位盘号>`。

   扫描 922 个文件（含各盘重复的安装程序、数据文件），立即数形式的调用用到了分发表里 82 个有例程的功能号中的 68 个；没用到的是 `$15`、`$18`、`$27`、`$43`、`$44`、`$46`、`$47`、`$48`、`$54`、`$76`、`$77`、`$79`、`$7A`、`$81`。

   `game-launch.mjs <游戏序号>` 驱动“游戏集锦”软盘，停在写 `$4301` 处导出启动桩所在的 ERAM，再选择游戏、按 START，把读盘记录、ERAM、扩展 RAM、扩展显存与寄存器导出到 `out/game/<序号>/`（脚本开头用硬复位，可在同一个模拟器进程里反复运行）；`exe-api-scan.mjs` 静态扫描各程序里的系统调用并生成 [软件使用的系统调用](generated/软件使用的系统调用.md)；`pram-disasm.mjs` 把运行时装入扩展 RAM 的程序生成清单到 `out/disasm-pram/<场景>`。

3. 手动驱动模拟器（调试服务的命令表见 fcdev 仓库 `virtuanes/README.md`）：

   ```powershell
   node tools/sb2kdbg.mjs "run 60" "type dir\n" "run 100" "shot out/dir.png"
   ```

### 采集与调试的限制

- 模拟器窗口会显示出来；调试模式下画面只在每批帧的最后一帧刷新，`shot` 读取的是实时画面缓冲。
- 程序退出后立即输入命令，开头的一两个字符偶尔会丢失（`collect-cdl.mjs` 在每条命令前先按 3 次空回车来消耗掉，自己手动驱动时也可以这样做），重要截图要核对屏幕内容。
- 单步与断点停下后，当前帧剩余的 CPU 周期会在下次运行时补上，不影响指令级结果，但与 PPU 的相对时序会有轻微偏移。
- 清单只包含执行过的代码和可由静态追踪到达的代码（内核区，以及页组已知的换页功能）；其余没被覆盖到的页仍是 `.byte`，需要补充采集场景。静态追踪不会解析间接跳转（`JMP (地址)`）的目标。
- 工具只覆盖 ROM（BIOS）空间的静态追踪；扩展 RAM 里的程序只有执行过的代码进清单，且采集结束时才导出内容，页被后来的程序覆盖时以最后的内容为准。

BIOS 的源码在 [bios/](../../bios/)，是手工维护的，修改 BIOS 就是修改它。把 ROM 转成源码的一次性工具（原 `bios-gen.mjs`、`bios-promote.mjs`、`bios-decode.mjs`、`bios-label.mjs`、`bios-xref.mjs`、`bios-extract.mjs`）已删除，不再从 ROM 重新生成源码。

## 4. 分析流水线

**分析流水线**（`bios-analysis.mjs`，现在只给 `bios-report.mjs` 用）：实测 CDL（5 个运行场景合并）→ 静态追踪补全（`static-trace.mjs`，含内联跳转表）→ 划分代码段 → 启发式识别（`code-heuristic.mjs`）→ 生成清单（`bios-listing.mjs`，含地址表、立即数地址对、符号名）。汇编语法、局部标签与多文件拼接见 [bios/README.md](../../bios/README.md) 与 `bios/tools/asm6502.mjs` 的文件头。

## 5. ROM 页地图

ROM 共 128 页，每页 4K。固定内核区是第 4-7 页，汇编地址 `$C000-$FFFF`。其余页被“换页功能”映射到 `$8000-$BFFF`：一个页组由连续 4 页组成，调用时把页组的第 1 页映射到 `$8000`，所以同一页在不同页组里可能出现在不同窗口，工程里只取执行最多的窗口作为汇编地址。

| 页 | 汇编地址 | 内容 | 处理 |
| --- | --- | --- | --- |
| 0-2 | `$8000-$AFFF` | 页组 0：DOS 命令外壳，兼作运行库，供外部程序显示文字、换行等（入口见 系统调用手册 的 5.4 节） | `src/dos-shell/`、`src/dos-commands/` |
| 3 | `$B000` | 数据：DOS 外壳消息表（`LIB_PRINT_MESSAGE` 把它映射到 `$B000`，按消息号在 `$B200`（小字体）或 `$B500`（大字体）的 3 字节表（页号、地址低、地址高）里查字符串，如 `AUTOEXEC.BAT`、`<DIR>`） | `assets/p03-p03.bin` |
| 4-7 | `$C000-$FFFF` | 固定内核区：中断向量、系统调用分发器、硬件服务、跨页读写等 | `src/kernel/` |
| 8、9、A、B | `$8000` | 页组 `$08`、`$09`、`$0A`、`$0B`：文本显示（`$3B-$46`）及其他换页功能，各占第 1 页 | `src/display/`、`src/math/`、`src/window/`、`src/image/` |
| C-D | `$8000-$9FFF` | 页组 `$0C`（和下面的页 E 一起）：中文输入法服务（功能 `$6D`），`IME_SUB_TABLE` 是 37 个子功能的入口表，子功能 0-16 在这里；页 C 中部、页 D 开头有大块数据：拼音音节表（408 条）、两字母组合表、标点与全角转换表，格式见手册 5.10 节（还没按数据拆成资源文件） | `src/input-method/ime-services.asm`、`src/input-method/ime-dictionary-lookup.asm` |
| E | `$A000` 及 `$8000` | 同一页有两种用途：页内偏移 `$0000-$023B` 是输入法服务的后半（按 `$A000` 汇编，子功能 17-36；页 D 末尾的子功能 16 跨页接到 `$A000`，`$A000` 是页 D 最后一条 BNE 的操作数）；偏移 `$0300` 起是页组 `$0E` 的打印机服务（功能 `$76-$7A`，按 `$8000` 汇编，用 `.rorg/.rend` 存放，约 1270 条指令） | `src/input-method/ime-extra-services.asm`、`src/printer/printer-service.asm` |

| 10-57 | — | 数据：字库。汉字区 16-87（GB2312 一二级汉字）从 ROM `$1C000` 起，每字 16×16 点阵 32 字节（前 16 字节是每行左半边、后 16 字节是右半边），到 `$50DFF` 结束；`$50E00` 起是 ASCII 8×8 点阵（码 `$20-$7F`）；`$51100` 起是 ASCII 8×16 点阵（码 `$20-$7F`）；`$51700` 起是符号区 1-9（846 个 16×16 点阵，约到 `$580C0`）；页 `$10-$1B` 不是这套字库，是输入法拼音词库（页组 `$10` 起映射到 `$B000` 窗口：开头是每项 2 字节的索引表，之后是以 `$FF` 结束的候选字表，`p0c-ime-dict.mjs` 验证），页 `$1A`、`$1B` 大部分是 0（词库的末尾部分）。位置公式见 系统调用手册 5.12 节 `$3B` 一行，由 `$3B` 的实际运算验证（`verify/cases/p08-text.mjs`）。读取、显示与修改用 `tools/bios-font.mjs` | `assets/p10-p57.bin` |

## 6. 命名、注释与地址约定

**地址与窗口**

- 固定内核页 4-7 在 `$C000-$FFFF`；页组 g 把 ROM 第 g..g+3 页映射到 `$8000-$BFFF`。
- 同一页可能在不同窗口出现，源文件按它被执行时的窗口地址汇编，需要时用 `.rorg/.rend`；标签带页前缀 `Pxx_AAAA`。

**命名与注释**

- 例程用动词开头的大写下划线名，按模块加前缀（`FP_`、`FS_`、`DISK_`、`SHELL_`、`IME_`、`PRN_`、`SOUND_`…）；内部分支标签保持 `Pxx_AAAA`，不逐个命名。
- 每个例程前一行注释写：作用、输入、输出、副作用；不确定的结论标“待确认”并写出缺什么证据。
- 变量命名按 RAM 地址：`RAM_xxxx`，确认含义后改成有意义的名字并在 `src/include/` 的符号文件里集中定义。
- 改名用 `tools/bios-rename.mjs`，改完必须构建并与原始 ROM 逐字节一致。

**标签与格式**

- 固定内核区的标签是 `K_XXXX`，已读懂的例程用 `symbols.mjs` 里的名字，系统调用入口是 `API_XX`；其余页里的标签是 `PNN_XXXX`（`NN` 是目标所在的页号，`XXXX` 是汇编地址）。
- 写入类指令（`STA`、`STX`、`STY`、`INC`、`DEC`、移位）的地址视为硬件或内存目标，不生成标签；其他读取、跳转、分支的地址落在工程内时用标签表示，落在某条指令中间时写成“标签+偏移”。
- 汇编行末尾的 `; $XXXX` 是该指令的汇编地址；`推断` 表示是静态追踪推出来的、没被运行场景执行过；`启发式` 表示是启发式识别出来的（见下），属于推测；数据行末尾写明数据类别（未访问、数据、指令残留、指令边界不一致）。

**符号与地址表**

- 低于 `$8000` 的地址用 `src/include/` 里的符号名（`ramName()` 的命名：已确认含义的用有意义的名字，其余按区域用 `ZP_xx`、`RAM_xxxx`、`PPU_xxxx`、`IO_xxxx`、`WRAM_xxxx`、`ERAM_xxxx`）。绝对寻址且地址低于 `$0100` 的写法保持数字，避免汇编器改成零页。
- 立即数成对写入相邻地址（`LDA #低 / STA 地址 / LDA #高 / STA 地址+1`，两个方向都认）且合成的值指向 ROM，或指向 `$0600-$07FF`、`$6000-$7FFF`（只认存进零页的）时，改写成 `#<符号`、`#>符号`；写进 `$063E`、`$063F`（功能号与子功能号）的不算；`$8000` 以上落在别的页组里的值无法换算，保持数字。
- 地址表输出 `.word 标签,…`：静态追踪得到的内联跳转表（`JSR` 之后紧跟的地址表，按追踪出的项数），以及在未执行的字节里连续出现 4 项以上、每项都指向有效指令起点的地址（多数项低字节为 0 的不算，那是按键映射之类的数据）。表被别的指令引用到中间位置时在该处截断。
- 启发式识别（`code-heuristic.mjs`）：只在代码段内没被读写过的连续区间里，从区间起点（或起点之后 16 字节内）沿控制流递归下降，要求可达范围全是合法官方指令且没有 `BRK`、每条路径以 `RTS`/`RTI`/`JMP` 结束或接上已有指令、不走出区间、`JSR`/`JMP` 目标在可执行范围且不落在别的指令中间，可达指令不少于 4 条（偏移出来的候选不少于 10 条）。

## 7. 已知限制

以下是工程本身的限制（不是 BIOS 的问题）；BIOS 与硬件的未确认事项见 [问题与结论登记](问题与结论登记.md)。

1. **仍有少量地址常量是数字。** 不是成对写入相邻地址的立即数（比如 `LDX #低 / LDY #高` 传参）、高低字节分开存放的地址表（`LDA 表低,X / LDA 表高,X`）、落在别的页组里的地址，还没有符号化；修改 BIOS 后如果代码长度变化，需要逐个改。
2. **间接跳转目标没有解析。** `JMP ($xxxx)` 与 RAM 里的跳转向量的目标，只有出现在上述地址表里的才被识别为代码。
3. **跨页引用只部分符号化。** 页组 `$00`、`$08`、`$0C`、`$58`、`$5C`、`$5E`、`$60` 里 `JSR`、`JMP` 与读取类指令指向别的源文件的地址，已用当时的工具（`bios-xref.mjs`，已删除）改成“标签+偏移”（还有约 12 处落在没有标签的位置，保持数字）；页 09 前半部分、页 0E 后半部分等“同一页在两个窗口位置都执行”的区域已用 `.rorg` 分开汇编。页 0A、0B、0F、78 等其余多用途的页，源文件里只采用了执行最多的那个窗口地址；固定内核区调用换页功能时只有功能号，没有页内标签。
4. **未识别的连续区间。** 代码段内还有约 2 万字节没有归入指令，运行 `bios-report.mjs` 可以看到：全零填充（如 `p5D` 的 `$9422`、`p0A` 的 `$8CD8`）、被读写过的数据、少量不满足启发式条件的区域；要逐个人工判断。
5. **启发式的误判。** “启发式”标记的指令是推测：从短例程的操作数中间起头、再接上后面真实代码的，会把前面那几个字节误解码成指令（如 `$F3CF` 的 `ASL $60`，已手工改成 `STA SYS_ARG_10` 的一部分）；子功能表被拆成低字节、高字节两个数组时，表项指向的例程也可能没被识别（如声音服务的 `SOUND_SUB_TABLE`，已手工改成 `.word`）。改动这类区域前先用 `bios-dis.mjs` 核对。
6. **数据页没有完全解读。** 字库中 `$50`、`$52-$57` 页是补充汉字点阵（格式同 GB2312 字库，编码对应没有确认），图形（页 `$79-$7F` 的 10 张压缩图片，格式已解读）之外的其余表（候选字表等）要逐项确认格式后再整理成资源文件与 `.incbin`。
