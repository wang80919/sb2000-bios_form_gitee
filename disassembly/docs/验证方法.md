# 验证方法

本文说明怎样判定“一个例程或功能号验证过了”，以及怎样补用例、运行和统计。当前各功能号的验证进度见 [计划与进度](计划与进度.md)，具体用例的编号、依据与结果见 [验证证据清单](generated/验证证据清单.md)。

## 1. 验证状态口径

“全部确认”按下面五级给每个例程定状态，每个例程必须落在其中一级，并写进验证证据。

| 状态 | 含义 | 依据 |
| --- | --- | --- |
| 已验证 | 有预期值的用例调用过它，结果与独立算出的预期一致 | `verify/cases` 里带 `expect`/`check` 的用例通过 |
| 已执行 | 在模拟器里真的执行过，但没有预期值校验（只确认反汇编的指令序列能跑、没有崩溃） | CDL 指令标志 |
| 桩执行 | 例程依赖没有的硬件，用桩（固定返回值）让它跑完 | 用例里写明桩的内容 |
| 不可达 | 确认没有任何调用路径或条件永不成立 | 写明理由与证据（调用图、跳转表、条件） |
| 仅代码阅读 | 只读过代码，没有执行 | 只允许是过渡状态，最终清零 |

规则：

- 状态以实测为准，注释里的“推断”“启发式”只是生成工程时的来源标记，不代表验证状态。
- “已执行”的例程要继续补预期值用例升级为“已验证”，优先级按对修改 BIOS 的影响排：被调用多的、含算法的、含数据格式的先做。
- 预期值必须来自独立的计算或已知语义（整数除法、十进制算术、文件系统规范），不能把 BIOS 的输出抄回来当预期。
- 模拟器已实现全部硬件（并口打印机、语音端口、软驱等），把它当作真机：硬件相关的例程直接实测，行为以模拟器源码为参考。“桩执行”只用于模拟器确实没有的东西，“不可达”只用于没有调用路径的代码。

## 2. 补验证用例的做法


1. 用 `verify/cases/sweep-api.mjs` 对每个功能号、每个子功能做一次通用参数调用，先把能跑到的跑到。
2. 看 `npm run coverage` 里没执行完的例程，读代码判断条件，补专门的用例（构造输入让条件成立）；DOS 外壳、输入法、文件系统等要键盘或磁盘状态的，用场景脚本（`collect-cdl.mjs` 的场景）增加操作。
3. 依赖硬件的例程做桩或标不可达。
4. 给有明确语义的例程补预期值，升级为已验证。

## 3. 用例的规范

用例文件的格式、字段与运行方法见 [verify/README.md](../verify/README.md)。要点：

- 每个用例有唯一编号，按模块分文件（`verify/cases/<模块>.mjs`），文件头注释写明预期值的来源（哪段代码阅读、哪条规范）。
- 有预期值的用例用 `expect` 或 `check`；只跑到的用例不写预期。
- 预期值必须来自独立的计算、已知语义或代码阅读写成的模型；用例按功能的业务语义写，不能只按实现写。
- 用例必须能无人值守重放；挂起会让模拟器重启，不影响后面的用例。
- 模拟器的存档读取会崩溃，不要用 `loadstate`。
- 用例要在默认（完整开机）ROM 下通过，快速开机只用于开发时省时间。完整开机后定时器、键盘的 IRQ 随时可能来，记录寄存器写入、改写中断钩子的用例要在用例里写 `sei: true`（桩代码先 PHP、SEI，调用后 PLP）；会弹“Print to...”对话框的打印机用例要给足帧数（`maxFrames` 大于 120），等自动应答；按帧数计时的用例（如 `$1B`）的范围要同时适合两种开机方式。
- 每次复位开机（`resetToDos`）时，工具先发 `audio fast` 让模拟器不再等声卡按真实时间播放开机音乐，开机完成后发 `audio real` 恢复。开机音乐按真实时间播放要约 3.5 秒，加速后一次开机约 1.3 秒（原来约 4.8 秒）；实测两种方式开机后系统 RAM 的哈希与 PC 完全一致，模拟器内部时序不变。只加速开机阶段，用例运行中的语音与 WAV 仍按真实时间，所以这里不验证声音的时长，只验证 BIOS 逻辑。

## 4. 快速开机 ROM

快速开机 ROM 只用于调试：它不执行页 78 的开机程序，实测与原版在提示符处有 71 个系统 RAM 字节、 7 个扩展 RAM 字节不同（多为开机程序留下的参数、栈残留和临时变量，鼠标光标初始位置不同），`dir` 等基本命令正常，其余影响未逐项确认，所以不用它得出验证结论，也不用它采集 CDL。

## 5. 命令

| 用途 | 命令 |
| --- | --- |
| 运行验证用例（`--only 前缀` 只跑一部分，`--fast` 用快速开机 ROM） | `node tools/verify-run.mjs [--attach] [--only 前缀] [--fast]` |
| 覆盖率（按文件、按例程） | `npm run coverage`，或 `node tools/bios-coverage.mjs --page p09 --routines 4` |
| 功能号验证状态（有例程的功能号里哪些已有带预期值的用例） | `node tools/api-verify-status.mjs` |
| 验证证据清单（完整运行验证并统计覆盖率，3800 多个用例约 2.5 小时） | `npm run evidence` |
| 临时调用一次例程 | `node tools/rom-call.mjs func=4B sub=0 mem=069A:640007 read=069A:3` |

每次修改汇编或工具后的检查：`node tools/bios-build.mjs`（逐字节一致）、`npm test`、必要时 `node tools/verify-run.mjs` 与 `npm run coverage`。
