# 反汇编文档地图

`disassembly/docs/` 的文档按职责分成四类。每条事实只写在一份文档里，其他文档用链接引用，不重复。

## 1. 过程文档（手写）

| 文档 | 职责 | 读者 |
| --- | --- | --- |
| [计划与进度](计划与进度.md) | 目标、阶段、已完成什么、正在做什么、下一步；统计数字与用户已确认的决定 | 接手工作的人 |
| [验证方法](验证方法.md) | 验证状态口径、补用例的做法、用例规范、验证命令 | 写验证用例的人 |
| [工程说明](工程说明.md) | `disassembly/` 的目录、命令、采集流程、ROM 页地图、命名与地址约定、工程的已知限制 | 使用与维护反汇编工具链的人 |
| [问题与结论登记](问题与结论登记.md) | 发现的问题：已更正的旧结论、原程序的特点与缺陷、模拟器缺陷、挂起调用、待确认、待重新验证 | 所有人 |

## 2. 生成文档（`generated/`，脚本生成，不要手改）

| 文档 | 内容 | 更新命令 |
| --- | --- | --- |
| [例程规格表](generated/例程规格表.md) | 每个例程的地址、说明、输入输出寄存器、副作用 | `npm run docs` |
| [内存变量与硬件寄存器表](generated/内存变量与硬件寄存器表.md) | 变量与寄存器的地址、含义、读写者 | `npm run docs` |
| [调用图](generated/调用图.md) | 例程之间的调用关系 | `npm run docs` |
| [BIOS 数据区清单](generated/BIOS数据区清单.md) | 数据块的种类、格式、引用者；人工说明在 `bios/data-notes.json` | `npm run docs` |
| [待补充清单](generated/待补充清单.md) | 阶段 D 的待办：源文件里的“待确认”、没有说明的例程、含义未确认的变量 | `npm run docs` |
| [系统调用表](generated/系统调用表.md) | 系统调用分流表、已知符号与实测调用次数 | `node tools/render-api-doc.mjs` |
| [软件使用的系统调用](generated/软件使用的系统调用.md) | 官方软件里各系统调用的使用次数与使用者 | `node tools/exe-api-scan.mjs out/official` |
| [验证证据清单](generated/验证证据清单.md) | 每个有预期值的用例、依据与结果，挂起的调用，各页覆盖率 | `npm run evidence` |

## 3. BIOS 修改指南（`drafts/`）

怎么修改 BIOS 并验证的指南。面向应用开发的系统调用手册、硬件说明与开发指南在与本仓库同级目录的 fcdev 仓库的 `docs/sb2000/` 里维护。

| 文档 | 内容 |
| --- | --- |
| [修改 BIOS 指南](drafts/修改BIOS指南.md) | 在 `bios/` 上修改 BIOS、构建、验证的流程与三个完整示例 |

## 4. 研究报告（`research/`）

| 文档 | 内容 |
| --- | --- |
| [NES 兼容模式研究](research/NES兼容模式研究.md) | 在 SB2000 上运行 NES 游戏：游戏软盘的装载、FC 兼容模式的硬件行为、DOS 下的 `play`、限制与方向 |

## 5. 什么内容写在哪

| 内容 | 写在 |
| --- | --- |
| 做到哪了、下一步做什么 | 计划与进度 |
| 怎么判断验证过了、怎么写用例 | 验证方法 |
| 目录、命令、页地图、命名约定 | 工程说明 |
| 发现了什么问题、什么还没确认 | 问题与结论登记 |
| 系统调用怎么用、硬件怎么工作 | fcdev 仓库 `docs/sb2000/` |
| 每个例程、变量、数据块是什么 | 生成文档 |
