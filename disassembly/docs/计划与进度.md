# 计划与进度

本文是反汇编与整理工作唯一的计划与进度记录：目标、阶段、已完成什么、正在做什么、下一步做什么。每完成一个阶段或子阶段就更新本文；验证口径见 [验证方法](验证方法.md)，发现的问题与结论见 [问题与结论登记](问题与结论登记.md)，工具与目录见 [工程说明](工程说明.md)。

统计数字都注明了日期与统计命令，以命令的当前输出为准。

## 1. 目标与交付物

最终要把 SB2000 的 BIOS 固件反汇编、验证，整理成一套可以开源给别人用的完整资料：

| 交付物 | 位置 | 完成标准 |
| --- | --- | --- |
| 反汇编过程资料 | `disassembly/` | 分析与验证工具、验证用例、过程文档；每个例程的验证状态明确（口径见 [验证方法](验证方法.md)） |
| 正式 BIOS 源码工程 | `bios/` | 开发项目的形态：按功能分目录与文件，文件名、标签、变量都有含义，每个文件有文件头、每个例程有头注释，源码里没有生成工具留下的行尾标注；用自写的汇编器 `asm6502.mjs` 构建（不转 ca65），结果与原始 BIOS 逐字节一致；改汇编后能重新构建，在模拟器里运行调试（有流程说明） |

反汇编过程的全部工具、验证用例与过程文档留在 `disassembly/`。面向应用开发的 SDK、系统调用手册、硬件说明与示例程序在与本仓库同级目录的 fcdev 仓库（`examples/sb2000/`、`docs/sb2000/`）里维护，不属于本仓库。

### 3.3 做法

1. 先读代码，把每个功能号的参数、子功能、分支写成独立的模型；用官方软件的真实调用取合法参数，按使用次数排优先级（`docs/generated/软件使用的系统调用.md`）。
2. 用例按功能的业务语义写，预期值来自模型或独立算术，不抄 BIOS 的输出；跑出不一致时先判断是模型错还是原程序的特点，原程序的特点记入 [问题与结论登记](问题与结论登记.md)。
3. 每个子阶段完成后：`node tools/bios-all.mjs --write`（重建一致、149 个单元测试、生成文档），把验证结果同步到 fcdev 仓库 `docs/sb2000/02-系统调用手册.md` 里对应的行（可靠程度改为“已验证”），更新本文。

## 5. 后续整理阶段（S2-S5）要点

- **S2 正式 BIOS 源码工程**（2026-11-10 的统计：17 个汇编文件，45130 行，指令 36144 条；标签 4874 个，其中 3405 个是 `P00_802C` 这样的自动名；注释行 1073 行；每条指令后有地址注释，另有 2963 条“启发式”、16867 条“推断”、1108 个数据块“未访问”的行尾标注；`equates.asm` 1005 行、810 个含义不明的符号）：
  - 源码放 `bios/`，汇编器与构建脚本移到 `bios/tools/`，`disassembly/` 的分析、验证工具通过 `tools/config.mjs` 引用 `bios/`。
  - 按功能分目录和文件，名字用功能名；一个文件是 ROM 里连续的一段，不打乱顺序，保证逐字节一致；具体切分在 S2.1 先统计各页例程的调用关系再定。
  - 删除全部行尾标注；构建时由汇编器输出“源码行到 ROM 地址”的映射，依赖行尾地址注释的工具改读映射；“启发式、推断、未访问”只出现在生成的覆盖报告里。
  - 例程入口都有有含义的名字和头注释（作用、输入、输出、副作用、调用者）；例程内部的跳转目标用局部标签（`@名字`，作用域到前一个全局标签为止，需给 `asm6502.mjs` 增加），自动名清零。
