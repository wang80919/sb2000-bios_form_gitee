## 3. 模拟器缺陷与修复

验证时把模拟器当真机，所以模拟器本身的错误会表现为“BIOS 有问题”。遇到类似现象先查这里。模拟器的编译方法见 fcdev 仓库 `virtuanes/README.md`。

| 编号 | 现象 | 原因 | 修复 | 验证 |
| --- | --- | --- | --- | --- |
| E1 | 写语音端口 `$4302` 的字节不进语音合成器；读 `$4302` 状态永远是 `$80`；语音服务 `$75`、`$74` 子功能 10 及以上调用后不返回，连续运行时 NMI 里的发送程序耗尽栈 | 旧版模拟器的 `NES/Mapper/MapperSB2K.cpp` 的写寄存器函数里，把字节放进语音环形缓冲的代码紧跟在 `case 0x4301:` 的 `break;` 之后，前面缺少 `case 0x4302: // speech port` 标签，这段代码永远执行不到 | 旧版里在 `#ifdef LPC_DRYRUN` 前补上该标签后重新编译；2026-11-10 起使用的上游较新版自带该标签，不用再补 | `p04-speech.mjs`：`$74` 子功能 10-13 与 `$75/$00` 都能发完最小语音流后由 BIOS 写 `$0F`、清 `$0328/$0329` 并返回 |

## 4. 验证中遇到的挂起调用

全功能扫描（`verify/cases/sweep-api.mjs`）中有 89 次挂起、178 次因同组连续挂起被跳过，按原因分类如下（“待补”表示还没有专门用例）：

| 功能号 | 现象 | 原因 | 状态 |
| --- | --- | --- | --- |
| `$1B` | 等待超时 | 扫描的 X=0 即等 256 帧，超过 30 帧上限，不是缺陷 | 已验证（`kernel.1b.wait-scales`） |
| `$25` | 执行 PPU 寄存器区的垃圾 | 通用参数没有合法的调用目标 | 已验证（换入页组 `$09` 调除法，`kernel.25.call-banked`） |
| `$26`、`$1D` | 不返回 | 设计如此（换页跳转、longjmp 式恢复上下文）；`$26` 在开机时进入页组 0 已在场景里执行过 | 不可达（返回式调用） |
| `$49`、`$55-$58`、`$62-$64` | 执行跑飞 | 超出页组入口内联表（页组 `$0F` 表 2 项、`$09` 表 11 项、`$0B` 表 8 项），表后面紧跟内联跳转例程自己的代码，读出的“地址”是代码字节拼成的：`$49`→`$A80A`，`$55`→`$A80A`，`$56`→`$8568`，`$57`→`$6810`，`$58`→`$1185`，`$62`→`$A80A`，`$63`→`$8568`，`$64`→`$6810`，都不是有效的例程入口（`$57`、`$58`、`$64` 的目标还在 `$8000` 以下） | 不可达（无合法例程；依据 `test/dispatch-real.test.mjs`） |
| `$66` | 执行跑飞（原来被误当成表外功能号） | 分发器在 `$FDD3` 单独比较 `$66`，直接进入页组 `$0F` 的 `$8700`，不经入口内联表，所以它有例程（卡拉 OK 歌词滚动，`KARAOK.EXE` 调用，见 Q22） | 有例程，已验证（`tools/probe-karaoke.mjs` 运行 `KARAOK.EXE`，见计划与进度 C12） |
| `$34` | 原来被误列为不可达 | `$34` 在 ROM 表里指向 `$F267`，有例程 | 已验证（`p04-kernel-dma.mjs`） |
| ROM 表里指向“未实现”桩例程的 23 个功能号（`$16`、`$20-$23`、`$2D-$2F`、`$35-$3A`、`$67-$69`、`$6E-$73`）与大于 `$81` 的功能号 | 直接返回 | 桩例程 `$E150` 是 NOP、NOP、RTS，分发器对大于 `$81` 的功能号直接走返回；调用开头把 `$0640` 清 0，参数区与 A、X、Y 不变 | 已验证（`p04-kernel-nofunc.mjs`，28 例） |
| `$00-$0F` | 查 RAM 表（`$05FA` 起，每项 3 字节：页组、地址低、地址高） | 由程序运行时登记，BIOS 里没有对应例程 | 已验证（`p04-kernel-ramtable.mjs`，16 例：每个功能号登记成页组 `$08`、地址 `$E43E` 后调用）；其他页组的窗口映射没有逐个核对 |
| `$17`、`$6B` 子功能 0 | 调用后返回（约 42 帧） | 扩展扫描中的挂起是因为前面用例留下的键盘状态；开机后单独调用都能返回 | 已验证（`kbd.init-17`、`kbd.init-6b0`） |
| `$6A` 子功能 2 | 等手柄按键 | 按键已注入时立即返回 | 已验证（`pad.wait`） |
| `$6B` 子功能 4 | 等按键 | 队列里已有按键时立即返回 | 已验证（`kbd.wait-key`） |
| `$59`、`$5C`、`$5E`、`$5F`、`$60` | 跑飞或超时 | 需要合法的窗口、图片、映射数据参数 | 已验证（`p0a-window.mjs`、`p0b-map.mjs`、`p0b-image.mjs`） |
| `$74` 子功能 10-13、`$75` 子功能 0 | 模拟器修复前不自己返回 | 写 `$4302` 的字节在模拟器里不进语音合成器（源码缺 `case 0x4302:`，已修复） | 已验证：发送序列、指针推进、`$4026`、播完后返回（`p04-speech.mjs`） |
| `$75` 子功能 1、2 与 `$75/$00` 的 NMI 发送方式（`$032B` 位 0 为 1） | 修复后可返回（命令 `$0B` 时旧版模拟器的语音合成器不给播完状态，调用不返回；上游较新版给出播完状态，调用能返回） | 词条表、播放列表、NMI 逐字节发送都用特制数据发送 | 已验证（`p04-speech.mjs`：子功能 1 序号 0、1、越界，子功能 2 一项、两项、三项（含越界项），`$032B` 位 0、2、3 的各种组合，等待帧数用调用日志核对） |
| `$7C` 子功能 5、6，`$7D` 子功能 0、2，`$7F`，`$80` | 等待磁盘 | 通用参数没有合法的文件句柄、路径与磁盘参数 | `$7C/$05`、`$06`、`$80/$02-$05` 已验证（`p58-fs-handle.mjs`、`p5c-disk.mjs`）；`$7D/$02` 已验证；`$7D/$00`、`$7F` 与 `$80` 其余子功能只跑到 |

| U14 | 输入法按键处理中没有验证的路径 | 输入法序号 3-6（外挂模块）的按键处理；联想方式（ERAM `$6902` 位 0）下的所有按键；Ctrl+F3 切换联想方式（等待按键）；ERAM `$6900` 低 4 位大于 9 时的按键分发（读到分发表之后的字节）；输入法模型遇到这些路径会抛异常，用例不走到它们；真实外挂模块（`WBX.BIN` 等）的转发目标没有验证，只验证了转发本身（页组设成 `$0C`，见 `p0c-ime-state.mjs`） |
| U15 | 打印机服务中没有验证的路径 | `$00-$1F`（用户字库）与 `$F8` 区以上汉字取字走用户字库表（`$067E` 起）；打印机未就绪时 `$0640` 置 `$FF` 的出错分支（`PRN_SEND_BYTE` 的超时、`PRN_SUB_07` 的超时）；`$0391` 不为 0 时真正的外挂打印驱动；`$0E` 对并口各位的设置只核对了 `$038F` 的变化；模型遇到用户字库路径会抛异常，用例不走到 |
| U16 | 文件与磁盘服务中没有验证的部分 | 已验证（2026-11-11，用模拟器的 `fdc` 命令注入软驱故障，见 Q23）：软驱的出错状态（无盘 `$18`、未就绪 `$15`、未知盘片 `$1A`、写保护 `$13`、校验错 `$17`）、有坏扇区的磁道扫描与连读、`$80/$01` 格式化磁道、簇链中间遇到坏簇时读到哪里为止、`$7C/$0F`、`$10` 等文件服务读写失败的分支、子目录写满且磁盘已满时的创建、只读目录、`$7B/$0F`、`$7B/$05` 簇号超出 FAT 范围或新值超过 12 位的输入。仍未验证：① 各故障是模拟器按 uPD765 结果寄存器的含义注入的（找不到地址标志、没有中断、数据校验错、不可写、命令无响应、磁头不动），真机上控制器对这些情形的实际回应没有对照；② 中断处理程序读结果字节超时（`FDC_ERROR_FLAG` 非 0）这条产生 `$15` 的分支、ST1 位 4（超时、溢出）对应的 `$2B`、重试次数与耗时；③ `$80/$08` 在坏扇区以外的故障下的位图；④ 簇号折回缓存范围（簇 43691 起，偏移按 16 位算）的读写 |
