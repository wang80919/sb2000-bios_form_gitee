# NES 兼容模式研究

记录在 SB2000 上运行 NES 游戏的研究结论：游戏软盘的装载方式、FC 兼容模式的硬件行为、DOS 下的 `play` 程序，以及尚未做的方向。硬件行为的出处是模拟器源码 fcdev 仓库 `virtuanes/VirtuaNES/NES/Mapper/MapperSB2K.cpp`，“已确认”指在模拟器里实际运行验证过，真机均未测试。

## 1. 结论摘要

| 项目 | 结论 |
| --- | --- |
| 两种运行方式 | DOS 程序运行在 6576 模式，游戏运行在 FC 兼容模式（`$4301` 写 `$55`），两者不能共存；进入游戏后不能回到 DOS，只能硬复位 |
| 已能运行 | 在 DOS 下输入 `play 文件.nes`：mapper 0 与 mapper 4（MMC3），PRG、CHR 各不超过 128K，已用超级马里奥兄弟与双截龙2 验证 |
| 暂时不能运行 | PRG 或 CHR 超过 128K 的游戏（魂斗罗、忍者神龟、古墓丽影、超级魂斗罗X）、CHR-RAM 游戏、带 trainer 的文件、其他 mapper |
| 不能运行的原因 | 硬件上 `$5006` 选一个 128K 窗口，PRG 与 CHR 共用；MMC3 寄存器只能在窗口内选页。更大的游戏要由游戏自己改写 `$5006`，加载程序无法代劳 |

## 2. 硬件机制

### 2.1 进入 FC 兼容模式

| 操作 | 效果 |
| --- | --- |
| 写 `$5006`（`$55`、`$77`、`$DD`、`$FF`） | 选扩展 RAM 与扩展显存的 128K 窗口 0、1、2、3（窗口号 = `((值>>2)&2) \| ((值>>1)&1)`），同时清 MMC3 的 IRQ 允许并重排银行 |
| 写 `$4301=$55` | 退出 6576 模式、置 RAM 启动标志、复位 6576 外设寄存器、切换到标准 PPU，并复位 CPU（取窗口末尾的 RESET 向量） |
| 软复位（模拟器命令 `softreset`） | 只复位 CPU、手柄与 APU，映射器状态保持，所以游戏中软复位不会回到 BIOS 或 DOS |

### 2.2 MMC3 仿真下的 CPU 与 PPU 映射

窗口基址 = 扩展 RAM（显存）起点 + 窗口号 × 128K。

| 范围 | 映射 |
| --- | --- |
| `$C000-$FFFF`（CPU） | 固定为窗口末尾 16K（R6 位 6 为 0 时；为 1 时 `$8000-$9FFF` 固定、`$C000-$DFFF` 由 R6 选） |
| `$A000-$BFFF` | R7 选窗口内 8K 页，R7 只取低 4 位（16 个 8K） |
| `$8000-$9FFF` | R6 选窗口内 8K 页，R6 只取低 4 位 |
| PPU `$0000-$1FFF` | R0-R5 选 1K 页：R0、R1 为 2K 页（取偶数），R2-R5 为 1K 页，只取低 7 位（128 个 1K） |
| 上电状态 | R6、R7 都为 0，所以 NROM 之类的游戏不能直接放进去，必须先写寄存器 |

### 2.3 DMA（`$4048-$404F`）

| 寄存器 | 含义 |
| --- | --- |
| `$4048` | bit7 启动；bit5 为 1 时复制到 CPU 地址（逐字节写），为 0 时复制到显存 |
| `$4049` | bit4 为 1 表示源是扩展 RAM（否则为 BIOS ROM）；低 4 位是源字节地址的第 15-18 位 |
| `$404B` | 源字节地址的第 8-14 位（低 7 位） |
| `$404A` | 源字节地址的第 0-7 位 |
| `$404C/$404D` | 目的地址；显存时 bit15 为 1 表示扩展显存（再加 `$4300` 选的 32K bank），否则是内置 CHR RAM |
| `$404E/$404F` | 字节数，奇数会进为偶数 |

源地址按字节计、不要求对齐，所以 iNES 头占的 16 字节不用手动移位。模拟器里 DMA 是瞬时完成的，`play` 复制后没有等待；真机是否需要等待没有验证。

## 3. 游戏软盘的装载方式

“游戏集锦”软盘（`游戏.ima`）里只有 `GAME.EXE` 与 `AUTOEXEC.BAT`，游戏数据不在文件系统里，而是直接放在固定扇区：

| 扇区（LBA） | 去向 |
| --- | --- |
| 1448-1959 | 扩展 RAM `$00000-$3FFFF`（两个游戏的 PRG，各占一个 128K 窗口） |
| 200-711 | 扩展显存 `$00000-$3FFFF`（两个游戏的 CHR） |
| 104-105、125-128、712-725 | 窗口 2（`$40000` 起）的菜单程序 |

菜单显示前两个游戏已经全部读入内存，按 START 不再读盘，只是切换窗口。`GAME.EXE` 在 ERAM `$6900-$7FFF` 装入启动桩与菜单：桩把 4 个窗口各自的 NMI、RESET、IRQ 向量存到 ERAM `$7000-$7017`，再把每个窗口的 RESET 向量改成 `$7018`（`JMP $7431`），最后写 `$5006`、`$4301`。因此游戏中软复位会回到游戏集锦菜单，而不是游戏本身。

### 3.1 启动桩与菜单程序的细节

- **游戏进入 FC 兼容模式**（已确认（桩代码与运行观察））：`GAME.EXE` 在扩展 RAM（ERAM）`$6900-$7FFF` 装入启动桩与菜单程序，入口 `$6900` 跳到 `$6952`。桩经功能 `$29`（临时映射）依次映射 4 个 128K bank 的最后一页（页号 `$9F`、`$BF`、`$DF`、`$FF`），把各自 `$BFFA-$BFFF` 的 NMI/RESET/IRQ 向量存到 ERAM `$7000-$7017`（每 bank 6 字节），再把各 bank 的 RESET 向量改成 `$7018`（`$7018` 起是 `JMP $7431`），最后 `PLA / PLA / LDA #$55 / STA $5006 / STA $4301`（写 `$4301` 在 `$6A6E`）。写 `$4301` 会复位 CPU，经被改过的向量进入 `$7431`。`$5006` 写 `$55`、`$77`、`$DD`、`$FF` 分别选 bank 0、1、2、3
- **游戏集锦菜单**（已确认（代码阅读与实测））：菜单程序在 ERAM `$7431` 起：先把 `$5006` 设为 `$DD`（bank 2）并画屏，在 `$7473-$749F` 循环等待手柄；零页 `$D4` 是选中的游戏序号（两项之间切换）；确认后按序号写 `$5006`（`$55`/`$77`），再经该 bank 的原 RESET 向量（保存在 `$7002`、`$7008`）跳入游戏。所以游戏中软复位走的是被改过的 RESET 向量，回到这个菜单。实测菜单程序的首次手柄按键可能被忽略。手柄读取例程在 `$766D`：先用 `$D9`（菜单里没有写它，开头的清零循环把整个零页清 0）或 1 写 `$4016`、再写清掉最低位的值锁存，然后读 8 次 `$4016`，每次用 `ROR A` 把最低位移进进位、再用 `ROL $DA` 移进 `$DA`，所以第 1 次读到的 A 键落在 `$DA` 位 7、右键在位 0；`$DC` 为 0（同样没有别处写它）时再用同样的方法读 `$4017` 到 `$DB`。主循环每隔 5 次垂直消隐读一次，`$DA` 等于 `$08`（上）或 `$04`（下）时 `$D4` 在 0、1 之间切换并重画选中标记，等于 `$10`（Start）时确认；比较的是整个字节，同时按下几个键不会被识别
- **GAME.EXE 的读盘参数表**（已确认（读盘记录与停在 `$8083`、`$816B` 时的寄存器、内存））：`GAME.EXE` 在偏移 `$30` 起有 8 字节 `02 01 12 03 03 00 09 03`（盘 18、19 的第 3 字节是 `06`），接着是以 0 结尾的文件名 `MENU.BIN` 与 `READDISK.BIN`。这 8 字节不是模块列表，而是两组裸读盘参数 [面、磁道、起始扇区、扇区数÷8]，每个字节先与密钥异或：程序（`$8065-$807D`）把 `$8039` 起的 `MENU.BIN` 复制到 `$6543`，调用 `$7C/$03`（删除文件），盘上没有这个文件，`DOS_ERROR`（`$6300`）为 `2`，存入 `$8038` 当密钥；解出第一组读 8 个扇区（盘 20、21 是 LBA 123-130，盘 18、19 是 111-118），第二组读 LBA 100-107，都经 `$80/$04` 读进扩展 RAM 页 `$90`（`$6203`），之后用 DMA 把第一次的前 `$0600` 字节复制到 ERAM `$6900`（启动桩）、第二次的前 `$0F00` 字节复制到 `$7018`（`$7018` 起是菜单程序，`$7431` 是它的入口），最后 `JMP $6900`。读盘后 `DISK_STATUS`（`$6208`）不为 0 时（`$8CDE`）等一个键，再 `JMP $C000`。名字 `READDISK.BIN` 没有任何指令引用（只有 `LDA $8039,X` 复制到第一个 0 为止），实际只用到 `MENU.BIN`

## 4. DOS 下的 `play`

源码在 fcdev 仓库的 `examples/sb2000/play/src/play.s`，流程如下。

1. 取命令行里的文件名（`$6364` 起，大写、零结尾，首字节为分隔空格）放到 `$6543`，用 DOS 的文件接口打开并读入（参数见 系统调用手册 4.7 节）。文件最多读 `$040010` 字节，因为有的 `.nes` 文件末尾带说明文字，整个读入会超出扩展 RAM。
2. 检查 iNES 头：魔数、mapper、PRG 与 CHR 个数、trainer 标志。
3. 关 NMI 并屏蔽中断，用 DMA 把 PRG、CHR 复制到第 3 个窗口（`$5006=$FF`，扩展 RAM 页 `$E0-$FF`，显存 `$4300` 从 12 起）。放第 3 个窗口是为了避开 DOS 程序自己和文件缓冲所在的低位页。
4. 把 PRG 里的 RESET 向量改成 ERAM `$6100`，把启动桩复制到 ERAM，再在 `$6000` 写 `$5006=$FF`、`$4301=$55`。
5. 复位后启动桩按 mapper 设置 MMC3 寄存器、镜像，然后跳到游戏原来的复位入口。

放置方式：

| mapper | PRG | R6/R7 | CHR |
| --- | --- | --- | --- |
| 0 | 放在窗口末尾（32K 起于页 `$F8`，16K 起于页 `$FC`） | 32K 为 12、13，16K 为 14、15 | 放在窗口开头，R0-R5 为 0、2、4、5、6、7 |
| 4 | 放在窗口开头，银行号直接对应；PRG 不足 128K 时再把最后 16K 复制到窗口末尾 | 0、1，之后游戏自己设置 | 同上 |

镜像：iNES 标志 6 的 bit0 为 1 表示垂直，MMC3 的 `$A000` 写 0 为垂直，所以启动桩写 `(标志6 & 1) ^ 1`。

## 5. 测试结果

| 游戏 | mapper | PRG / CHR | 结果 |
| --- | --- | --- | --- |
| 超级马里奥兄弟（日美） | 0 | 32K / 8K | 已确认：标题画面、START 进入 1-1、手柄与卷轴正常 |
| 双截龙2（阿渊汉化） | 4 | 128K / 128K | 已确认：标题画面、开场中文剧情、过场动画正常；文件 768K，只有前 256K 是数据，后面是说明文字 |
| 魂斗罗（yclone 汉化） | 4 | 128K / 256K | CHR 超过 128K，`play` 提示 `Size not supported`（已验证） |
| 忍者神龟 激龟忍者传 | 4 | 128K / 176K | CHR 超过 128K，预期被拒绝（未实测） |
| 古墓丽影（南晶科技） | 4 | 256K / 256K | PRG、CHR 都超过 128K，预期被拒绝（未实测） |
| 超级魂斗罗X | 4 | 256K / 256K | PRG、CHR 都超过 128K，预期被拒绝（未实测） |

## 6. 已知限制

- 只支持 mapper 0 与 4、有 CHR（不支持 CHR-RAM）、不带 trainer、PRG 与 CHR 各不超过 128K。
- 游戏中软复位会重新开始游戏（RESET 向量被改成启动桩，再跳回游戏原入口），要回 DOS 必须硬复位。
- 复制后没有等待 DMA，真机上是否需要等待没有验证。
- 文件名要符合 8.3；命令行里的中文文件名没有验证。
- 复制期间会覆盖窗口 3 里 DOS 的数据（含 FAT 缓存），所以启动后不能再返回 DOS。

## 7. 以后可以做的方向

| 方向 | 说明 |
| --- | --- |
| 大于 128K 的 MMC3 游戏 | 需要游戏在换页时同时改写 `$5006`。思路：给游戏代码打补丁，把对 `$8000/$8001` 的银行寄存器写入改成同时选择窗口；或者借助 MMC3 的 IRQ 在固定位置换窗口。需要逐个游戏分析，不是通用方案 |
| CHR-RAM 游戏 | 目前拒绝 CHR 个数为 0 的文件。需要确认仿真里 CHR-RAM 的行为（是否有可写的 CHR RAM） |
| 其他 mapper | 如 UNROM、CNROM、MMC1：需要用 MMC3 的银行寄存器去模拟，通常要给游戏打补丁 |
| 带 trainer 的文件 | trainer 要复制到 `$7000`（ERAM），目前直接拒绝 |
| 存档与 PRG RAM | `$6000-$7FFF` 是 8K ERAM，是否带电池保存没有研究 |
| 软复位回 DOS | 可以研究给启动桩加一个组合键，检测到后写 `$4031` 重新进入 6576 并跳回 BIOS 复位入口 |
| 真机验证 | DMA 完成等待、启动桩时序、键盘串口在 FC 模式下的行为 |
| 运行菜单 | 做一个选择游戏的菜单程序，一次装入多个游戏（每个 128K+128K），像游戏软盘那样切换 |
